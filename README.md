# 專題完成版交付包

## 專題名稱

中檢工管待處理 LOT 自動追蹤與升級通知系統

## 交付內容

- `專題報告_完成版.md`：可編輯的系統分析與設計報告；封面班級、姓名、學號及指導老師欄位保留空白。
- `文件/專題報告_完成版.pdf`：報告 PDF 版。
- `原型/`：可在瀏覽器操作的前端展示原型（HTML、CSS、JavaScript）。
- `原型/tests/workflow.test.js`：主管鏈、回覆、達成結果及未達成升級的 Node.js 單元測試。
- `資料庫/schema.sql`：MySQL 資料庫設計初稿，含中檢、通知回覆、追蹤結果與逐級升級關聯。
- `圖表/`：系統情境、更新後的 LOT 回覆升級流程、ER 圖、架構及主管鏈圖檔與原始圖檔。
- `文件/原型畫面.png`、`文件/通知回覆畫面.png`：原型操作畫面。

## 如何開啟原型

1. 使用 Chrome、Edge 或 Firefox 開啟 `原型/index.html`。
2. 若瀏覽器不允許直接讀取本機檔案，請在 `原型` 資料夾開啟終端機執行：

   ```bash
   python -m http.server 8000
   ```

3. 瀏覽器前往 `http://localhost:8000`。
4. 可用「新增中檢紀錄」測試新增良品累計與移轉門檻；用「更新處置」記錄負責人、進度及預計完成日。
5. 開啟「通知紀錄」，按「記錄處置回覆」選擇回覆層級，填寫目前進度與預計完成日。稍後按「追蹤承諾結果」明確選擇「已達成」或「未達成」。
6. 選「已達成」只記錄追蹤結果；選「未達成」會在原通知保存結果，並建立通知給目前主管的上一級。可沿新通知繼續回覆和追蹤；生產經理及生管經理為協同角色，未達成時都通知生產副總，最高層級為董事長。
7. 「系統規則設定」可調整展示用重檢升級次數及注意／急迫等待天數；「重設展示資料」會回復範例 LOT、通知與規則。

## GitHub Pages 部署

推送至 `main` 分支後，GitHub Actions 會自動將 `原型/` 部署為 GitHub Pages 網站。網站網址為：

`https://cem8837.github.io/Shoko_Dial_MidQC_Remaining/`

首次部署時，請在儲存庫的 **Settings → Pages** 將 **Build and deployment** 的來源設為 **GitHub Actions**。

## 測試

在專題資料夾執行：

```bash
node --test 原型/tests/workflow.test.js
```

測試涵蓋確認的主管鏈、股長逐級升至董事長、生產經理／生管經理協同、回覆內容與預計完成日保存、已達成不升級、未達成通知上一級，以及董事長沒有更上一級的情況。

## 規則與範圍注意事項

- 主管鏈為董事長 → 總經理 → 生產副總 → 生產經理 → 課長 → 股長 → 組長；未達成時反向逐級通知上一級。生管經理與生產經理協同，不插入主管鏈。
- 重檢仍未達標 2 次、等待注意／急迫 3／5 天，是可調整的暫定展示值，不是已核定的工廠規範。未指定自動追蹤時限；原型必須由使用者手動追蹤結果，不會在預計完成日自動判定或排程提醒。
- 原型使用瀏覽器 LocalStorage，不連接 PHP 或 MySQL；資料只保留在目前瀏覽器，不會跨裝置同步。
- 通知、回覆與逐級升級都是瀏覽器內展示紀錄，原型不提供正式登入、權限控管，也不會實際寄送 Email 或推播。
- LOT、品號、工單、姓名、數量和通知均為虛構展示資料。請勿輸入真實員工個資或正式生產資料。
- 手寫流程中的 P 檢查至裁切線只作為生產背景；本系統處理中檢後新增良品累計及印刷移轉門檻，不管理 P 檢查或裁切作業。

## 正式後端方向

報告中的建議架構為 HTML／CSS／JavaScript／Bootstrap + PHP + MySQL。`資料庫/schema.sql` 需在 MySQL 環境匯入；前端展示原型不會自動呼叫該資料庫。PHP 正式實作尚待建立登入、角色權限、伺服器端驗證、通知回覆與追蹤交易、上一級升級通知、排程（若日後確認需求）、備份及正式通知服務。
